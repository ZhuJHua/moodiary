### i18n: slang, not gen-l10n

Strings are generated by slang 4.19. `flutter_localizations` only serves material's own strings.

| Word | Meaning | Used in |
|---|---|---|
| i18n | the mechanism: externalized strings, locale resolution, plurals, codegen | package `moodiary_i18n`, `i18n/`, `slang.yaml`, `dart tool/task.dart i18n` |
| l10n | the resolved strings object for one locale | `context.l10n`, top-level `l10n`, `context.muiL10n` |
| Localizations | Flutter's `Localizations` chain | only `GlobalMuiLocalizations` / `MuiLocalizations` / `MuiLocalizationsData` |

Do not call the App's copy `MoodiaryLocalizations` (it never goes through Flutter's chain), and do not name enum-to-label methods `l10nText` (see `Language.label`).

Two unrelated slang outputs in two modes:

| | Source | Mode | Symbols |
|---|---|---|---|
| App | `moodiary_i18n/lib/i18n/<ns>_{zh,en}.i18n.json` | default (`LocaleSettings` + `TranslationProvider`) | `Translations` / `AppLocale` / `l10n` |
| mui | `mui/lib/src/i18n/{zh,en}.i18n.json` | `locale_handling: false` + hand-written delegate | `MuiLocalizationsData` / `MuiLocale` / `context.muiL10n` |

- App: `TranslationProvider` is mounted in `runApp`; `applyStoredLanguage()` calls `LocaleSettings.setLocale` once. KV stores only the preference enum; `MaterialApp.locale` comes from `TranslationProvider.of(context).flutterLocale`.
- mui: its output has no `LocaleSettings`, `TranslationProvider` or top-level `muiL10n`, only `MuiLocale` and `MuiLocalizationsData`, wrapped by the hand-written `GlobalMuiLocalizations` delegate. A host adds it to `MaterialApp.localizationsDelegates`; a missing delegate falls back to the base locale. Components write `context.muiL10n.ok` (hand-written extension). mui strings always come from mui's own table, never `MaterialLocalizations`: material's wording changes with the SDK, and `MaterialLocalizations.of` asserts and crashes where `MuiLocalizations.of` falls back. Gate: `mui/test/i18n_test.dart`.

App namespaces: one file per feature, `common` plus `app` / `diary` / `assistant` / `export` / `sync` / `media` / `editor` / `ui` / `lock` / `share` / `picker`. Read as `l10n.diary.searchResult`; deleting a feature deletes its two files. Feature packages do not install slang themselves (mui is the only exception).

- Widgets use `context.l10n.xxx` (rebuilds on language change); services / export / callbacks use top-level `l10n.xxx` (does not rebuild). Parameters are named.
- After editing `*.i18n.json` run `dart tool/task.dart i18n` (output is committed, nothing catches a stale one).
- Dead-key check, run inside `moodiary_i18n` (about 9 s): `dart run slang analyze --full --source-dirs=../../../packages,../../../mobile`. It is a substring match on `l10n.`, so mui's `muiL10n.back` masks a same-named App key, and a local alias (`final t = l10n.assistant; t.x`) makes `x` look unused. Always write `l10n.xxx.yyy` in full and do not end other variables with `translate_var`.

Traps that raise no error:

1. `TranslationProvider` / `LocaleSettings` / `AppLocaleUtils` are hard-coded generator names; mui's output still contains `AppLocaleUtils` and an `export 'package:slang_flutter/...'`, so its barrel only does `show MuiLocalizationsData`.
2. Plural keys must have the same node shape in every locale, so Chinese sides are plural nodes with only `other`. slang has no zh plural rule and would `print` on every render; `setupPluralResolvers()` (before `runApp`) says zh always takes `other`. A future plural key in mui goes through the delegate's `buildSync(cardinalResolver: ...)`.
3. Non-base locales are deferred imports (`lazy: true`), so the App uses async `setLocale`, never `setLocaleSync`. mui pins `lazy: false` because its delegate returns a `SynchronousFuture` from `buildSync`; turning lazy on would break web. Gate: `mui/test/i18n_test.dart` checks for no `deferred as`.
4. `timestamp` and `flat_map` are off in `slang.yaml` (noisy diffs, an extra full map).

**The reader decides whether a string goes through slang**: text for the model (system prompt, tool descriptions, argument schemas, tool return text; `moodiary_assistant/lib/src/data/`) is hard-coded English, never i18n; text for the user goes through slang. The UI summary of a tool call is a separate string from `AssistantTool.summarize`. The two never share.

**Sync events carry no strings**: `SyncEvent` has only kind / level / reason / payload; the log page picks l10n by kind / reason. Add a `SyncEventReason` or payload field instead of a sentence. `SyncException` uses `l10n.sync.err*`. `_kindLabel` / `_kindIcon` are exhaustive switches, so a new kind without a string is a compile error.

**Chinese literals that stay**: `'宋体'` (font family), `'『压测』'` (stress-test diary title marker; historical data depends on it), the ICP filing number (legal identifier), `logger.e` / `assert` text (log files).

> `dart run slang migrate arb` must not be used: it splits keys into nested paths by camelCase, rewriting every call site and throwing on overlapping prefixes like `accentCustom` / `accentCustomTitle`.
